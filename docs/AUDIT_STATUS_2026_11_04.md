22 novembre 2026 — F2, démarrage et synchronisations multi-onglets (local uniquement). Un second chemin destructif a été identifié après le correctif précédent : le minuteur de démarrage appelait `discardTripConflicts({ silent: true })` après 600 ms. Il est retiré ; un test exécute les minuteurs pendant deux secondes et vérifie la conservation des erreurs, puis le fonctionnement du nettoyage explicite. Les anciennes fixtures neutralisaient `setTimeout`, ce qui avait laissé ce chemin hors du test de rechargement précédent.

Le rejeu utilise désormais `navigator.locks.request` en mode exclusif, avec `ifAvailable`, et un nom isolé par compte. Le compte est revérifié avant exécution. Le bail local et son renouvellement restent actifs pour les anciens clients et les environnements sans Web Locks. Si le gestionnaire refuse la demande, l'action n'est pas rejouée sans verrou. La libération du verrou navigateur suit la fin de la promesse, y compris après erreur.

Validation : 54 tests unitaires ciblés réussis ; deux tests Chromium avec deux pages réelles du même contexte réussis, succès et erreur/reprise. Le second onglet n'envoie rien tant que le premier attend, même en supprimant le bail local pour simuler son expiration ; le verrou navigateur est libéré ensuite et la reprise conserve le contenu. Ce n'est pas une garantie transactionnelle pour les modifications de localStorage, ni pour les anciens clients qui ignorent Web Locks. Les écritures concurrentes entre onglets restent ouvertes. Publication et APK explicitement différés par l'utilisateur.

Référence API consultée : https://developer.mozilla.org/en-US/docs/Web/API/LockManager/request (verrou exclusif, ifAvailable et libération à la résolution/rejection du callback).
